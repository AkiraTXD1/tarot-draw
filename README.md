# 静室 · 中文塔罗抽牌

一个可以直接离线运行的中文塔罗抽牌小程序。第二阶段同时提供原有文字牌面与一套经典公版 Waite-Smith 卡面，两种主题可随时切换；程序本身不调用网络服务。

## 使用方法

1. 保持本项目目录结构完整，尤其不要移动 `assets/cards/classic/` 中的卡面文件。
2. 双击 `index.html`，使用现代版 Chrome、Edge、Firefox 或 Safari 打开。
3. 问题可以留空。选择牌阵后点击“开始抽牌”。
4. 逐张点击牌背。全部翻开后，可以把记录保存在当前浏览器中。
5. 使用“牌组主题”选择文字版或经典牌组；偏好会保存在当前浏览器。
6. 历史记录位于页面底部，默认折叠。

不需要安装 Node.js、包管理器或任何第三方依赖。程序不调用 AI、API 或远程服务；经典卡面已经作为本地 WebP 文件随项目保存。

## 文件职责

- `cards.js`：完整 78 张塔罗数据，只负责牌库。
- `decks.js`：牌组主题配置，只负责显示主题与未来扩展入口。
- `script.js`：安全随机抽牌、正逆位、翻牌、界面状态和本地历史记录。
- `style.css`：牌背、文字/图像牌面、桌面/平板/手机布局和动画。
- `index.html`：页面语义结构和各功能入口。
- `README.md`：使用、扩展和检查说明。
- `DECKS.md`：双牌组结构、经典素材来源和添加第三套牌组的方法。
- `assets/licenses.json`：78 张经典卡面的逐张来源、许可与文件映射。
- `assets/cards/classic/`：78 张经过网页尺寸优化的公版 WebP 卡面。

抽牌数据、抽牌逻辑、主题配置与界面渲染互相分离。图片路径不会参与选牌或正逆位计算。

## 牌组主题

默认仍为“文字版”。在“准备抽牌”区域选择“经典牌组”后，当前已经翻开的牌、后续翻牌、总结卡和历史“查看总结”会立即改用经典卡面；切换不会调用 `drawCards()`，不会改变已经抽出的牌或正逆位。

主题偏好保存在 `localStorage` 的独立键中，刷新后继续使用上次选择。经典图片不存在或加载失败时，相应卡牌会自动保留完整文字牌面，不显示破图图标。

经典牌组采用 Wikimedia Commons 的 `Rider-Waite-Smith tarot deck (TaionWC)` 同套 1910 “Pam-A” 扫描。该分类包含 78 张，逐张元数据均标记为 `Public domain`、`Copyrighted: False` 与 Public Domain Mark。原始绘制者为 Pamela Colman Smith；逐张来源页、原文件 SHA-1、授权标签、下载时间与本地文件名见 `assets/licenses.json`，结构说明见 `DECKS.md`。

## 随机机制

程序只使用浏览器的 `crypto.getRandomValues()`：

- 选牌使用加密随机整数，并采用拒绝采样避免直接取模的分布偏差。
- 每抽出一张牌，就从本次临时牌池中移除，因此同一牌阵不会重复。
- 牌的正逆位由另一次独立随机读取决定，理论概率各为 50%。
- 整个牌阵的牌与正逆位，在点击“开始抽牌”的同步流程中一次性确定。
- 问题文本没有传入 `drawCards()`，只用于当前页面显示和保存记录。
- 翻牌动画、卡片点击顺序、窗口尺寸和点击速度都不会重新计算结果。

## 历史记录

历史记录使用 `localStorage`，只保存在打开页面的当前浏览器中。每条记录包含：

- 随机生成的唯一记录 ID
- 日期和具体时间
- 问题
- 牌阵
- 各牌位的牌名、正逆位与关键词

刷新或重新打开页面后，记录会从同一个存储键中重新读取。清理浏览器网站数据、使用隐私模式或更换浏览器会影响这些本地记录。删除单条记录、清空全部记录和放弃当前牌面都需要确认。

## 牌阵总结与截图模式

所有牌翻开后，详细牌面下方会自动出现“本次牌阵总结”。总结不会重新抽牌，也不会重新计算正逆位，只读取本轮已经冻结的结果。

总结包含问题、牌阵、牌位、抽牌时间、每张牌的中英文名、正逆位、关键词、对应牌义、结构化“整体走势”和便于 OCR 识别的“AI 解读信息”。整体走势只组合 cards.js 中已经存在的关键词与正逆位牌义，不调用 AI 或网络服务。

点击“分享 / 截图模式”会隐藏设置区、详细牌面、保存与重新抽牌按钮、历史记录、随机说明和页脚，只保留紧凑总结及退出按钮。再次点击即可恢复完整页面。

手机端布局：

- 1 张使用单卡布局。
- 2 至 3 张保持紧凑横排；三张牌已在 320、375、390、430px 宽度下验证无横向溢出。
- 4 至 10 张在手机端自动使用双列紧凑网格。
- 三张牌截图模式在 320px 宽、720px 高的测试视口内完整显示核心信息。

保存记录时会保存总结所需的 `cardId`、正逆位、牌位、meaning、symbol 和主题无关的图像映射。历史记录展开后可点击“查看总结”，并按当前主题重新渲染当时记录，不会触发随机。旧版本记录如果没有新增字段，会通过 `cardId` 从当前 78 张牌库补全对应牌义与卡面路径。

总结缩略牌兼容当前主题：文字版保留原 mini card；经典主题按需加载当前抽到的缩略卡面，逆位图片旋转 180 度，说明文字保持正常方向。

## 添加第三套牌组

每张牌的 `image` 现在是按主题索引的对象：

```javascript
image: {
  text: null,
  classic: "assets/cards/classic/major-00-fool.webp"
}
```

未来添加原创牌组时，在 `decks.js` 注册新主题、为卡牌图像对象增加同名资源键，并把文件放入独立目录即可。渲染函数会依据主题的 `imageKey` 自动选择资源；抽牌函数无需也不应该修改。完整步骤见 `DECKS.md`。

未来牌背图片预设为：

```text
assets/card-back.webp
```

当前牌背仍完全由 CSS 绘制。`assets/card-backs/` 已预留给未来拥有合法授权的牌背，并应保留现有 CSS 背景作为加载失败回退。
